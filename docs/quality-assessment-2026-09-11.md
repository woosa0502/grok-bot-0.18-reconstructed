## 구조적 약점 세 개

1. **두뇌가 둘이다.** Belmont 관리자와 Aside 세션이 각자 기억·규칙·프롬프트를 갖고 서로 텍스트로 넘긴다. 같은 지식이 두 군데(Belmont 지식 저장소 ↔ Aside 메모리)에 있고, 한쪽이 끊겨도 다른 쪽은 모른다.
2. **관측성이 없다.** "검색 결과에 사이트 페이지 0건" 같은 회로 단절을 알려주는 지표가 없다. 발견은 세션 기록을 손으로 뒤져서였다.
3. **모델 행동을 프롬프트로 조종하려 한다.** 규칙을 세 번 고쳐도 결정 횟수 중앙값은 15 그대로였다. 새 탭 처리, stale ref 재해결 같은 마찰은 브라우저·데몬 층에서 흡수해야 안정된다.

## 점수를 올리는 순서 (예상 공수)

1. **관측성 한 장 (0.5일).** 색인 파일 수, 검색 적중, 작업당 결정 횟수, 왕복 시간, 마지막 dreaming 시각을 하루 한 줄로. 있었으면 회로 단절을 당일 봤다.
2. **데몬 층 마찰 흡수 (1~2일).** 클릭으로 새 탭이 열리면 `page` 자동 전환, `RefStaleError` 시 새 스냅샷에서 같은 역할·이름으로 1회 자동 재해결. 매 실행 3~5회를 먹는 두 가지.
3. **두뇌 하나로 (1일).** 사이트 지식은 Aside 메모리 한 곳만 정본, Belmont 는 읽기만. 규칙도 한 파일에서 한 방향으로만 복사.
4. **세션 닫기 (0.5일).** 서비스가 끝난 세션을 닫아 dreaming·루틴 게이트가 원본처럼 차게.
5. **위젯 조기 종료 경로 복구 (0.5일).** `SendMessage final` 과 같은 방식으로.

여기까지 하면 7~8. 그 위는 WSL 을 벗어나거나(Windows 네이티브) 원본 업데이트 추적을 자동화해야 하는 영역이다.

## 오늘 확인된 사실 (근거)

- 답 뒤 빈 왕복: 7.4초 → 0.3초 (`SendMessage final`, 커밋 8970a60).
- 결정 횟수 A/B: 옛 규칙 13/19 → 새 규칙 15/15 → +스킬 17/12 → +패치 15/14 → +URL 이동 19/21(차단). 규칙으로는 안 줄었다.
- 메모리 회로: 909 원본은 심볼릭 링크를 색인하지 않음, 스킬 키워드는 ASCII 단어 경계 → 둘 다 패치(커밋 7a9049d). 재기동 후 색인 24파일/87청크.
- dreaming 절차 규칙(v2)으로 사이트 페이지 4개에 번호 절차가 생겼고, 다음 세션이 검색으로 꺼내 읽음.
- 쿠팡: URL 직접 이동 + 쿠키 지운 반복 접속 12회 → `사용권한이 없습니다`. 홈은 정상. 클릭 진입 상태는 미확인.
