# 타오바오 개인 직구 봇 — 계정 안전 & 자동화 경계 (2026-09-10)

Aside(에이전트 브라우저)로 **개인 직구를 보조**할 때, 내 계정이 阿里 风控(리스크컨트롤)에
false-positive로 막히지 않게 하는 원칙 정리. 대량 스크래핑·리셀·매크로 구매와는 성격이
다르지만, **그 "의도"는 탐지 시스템이 직접 못 본다**는 게 출발점.

---

## 0. 핵심 프레이밍 (한 줄)

목표를 **"Taobao에게 인간인 척하기"로 두지 말 것.**
→ **"중국어 UI를 대신 이해·조작해 사용자를 보조하는 브라우저 에이전트"** + 비가역/보안 단계는
사람이 승인하는 human-in-the-loop 구조. 이건 탐지 회피가 아니라 **정당한 개인 보조의 올바른 경계**다.

## 1. 법적 전제 (ToS) — "개인용이면 허용" 예외 없음

- **Taobao 2025-12-12 시행판**: 허가 없이 로봇·크롤러·자동화 프로그램 또는 사용자 조작을 모방하는
  방식으로 Taobao 콘텐츠를 취득·사용하는 것을 제한.
- **Tmall 2026-07-27 시행판**: 거의 같은 표현.
- 함의: "내 목적이 비상업적 개인용이라 선하다"가 **면책이 아니다**. 플랫폼은 먼저 *"이 세션이
  자동화인가?"* 를 기술적으로 판정하고, 그 다음에 위험도를 본다.

## 2. 가입·결제·배송 실측 (라이브 확인, 2026-09-10)

라이브 브라우저로 실제 페이지를 열어 확인한 값.

### 가입 (reg.taobao.com/havanaone/register)
- 페이지가 **한국(韩国 +82) 자동 감지**. 넣을 것은 딱 3가지:
  1. **手机号码** — 국가 `韩国 +82` + 본인 한국 휴대폰 번호
  2. **验证码** — `获取验证码`로 SMS 받아 입력
  3. 약관 체크 ×3 (서비스+Alipay 약관 / 개인정보 정책 / **만 19세 이상 확인**) → **同意并注册**
- **이메일·Gmail·구글로그인·비밀번호 칸 없음.** (비번은 이후 단계, 실명은 Alipay에서 나중)
- 관문: `获取验证码` 누르면 **滑块(슬라이드) 캡차**.
- → **가입은 사용자가 직접 하기로 결정.**

### 결제
| 수단 | 비고 |
|---|---|
| **Alipay(支付宝)** | 결제의 중심 축. 아래 카드들이 Alipay 안에 들어감 |
| ├ 해외 신용카드(Visa/Master/JCB) | **한국 카드 바인딩 가능** — 중국계좌 불필요 |
| ├ 중국 은행카드 / 花呗 / 余额(宝) | 중국 실명유저용 |
| WeChat Pay(微信支付) | 규제 상호연동으로 2024~ 도입 |
| UnionPay(银联) | 지원 |
- 단, 해외카드 바인딩·일부 상품엔 **Alipay 실명(KYC)** 벽.

### 배송 (한국 직배 됨)
- **판매자 海外直邮** (진짜 직배) / **官方 集运**(Cainiao 집운, 반직배) / **淘宝 글로벌 직배**(한국 포함 확대).
- 제한: 배터리·액체·식품·브랜드정품 등은 직배 불가/China-only 셀러 많음 → "海外直邮" 되는 상품만.
- 통관: 한국 **개인통관고유부호** 필요, 관세·부가세 대상.

### 소결
배송은 문제 아님. 실질 관문은 **가입 SMS + 결제 실명 + 캡차** 세 개.
봇이 못 만드는 건 딱 **현실 크리덴셜 2개**(SMS 받을 번호, 실명 Alipay+카드)뿐 —
이건 대행이 아니라 **사용자가 이미 가진 걸 1회 연결**하는 것.

## 3. 다차원 탐지(multi-dimensional detection)란 (Alibaba 공개 기술 기준)

**한 가지 증거로 봇 판정을 하지 않는다.** 클릭 간격 1.2초 하나로 "봇이다" 하는 게 아니라,
여러 축이 **서로 일관되는지 / 모순되는지**를 같이 본다.

| 축 | 무엇을 보나 |
|---|---|
| ① 네트워크 신원 | IP → 통신사/IDC 여부 → 세션 → 쿠키 → 장치식별자(Web UMID). "IP가 한국"만 보는 게 아님 |
| ② 프로토콜 지문 | UA(브라우저 주장) vs 실제 **TLS(JA3/JA4)** · **HTTP/2 지문** · Client ID. 겉은 Chrome인데 연결 지문이 Chrome이 아니면 **모순** |
| ③ 브라우저 환경(JS) | 페이지 안 JS 실행으로 창 높이·너비 등 fingerprint 수집. **자동화 노출**(navigator.webdriver/CDP 아티팩트)도 여기서 잡힘 |
| ④ 행동 신호 | Web SDK로 키보드·마우스·터치 probe 수, request behavior. 예) 상품 50개 요청 + 상호작용 거의 없음 + 일정한 시간패턴 + 비정상적으로 짧은 세션 = 조합 의심도↑ |
| ⑤ challenge 사다리 | JS Validation → Dynamic Token → **Slider CAPTCHA** → Strict CAPTCHA. 통과하면 일정 기간 **신뢰 쿠키** |

### A vs B (단순화)
- **A 사용자**: 한국 가정 IP + 기존 Chrome + 기존 쿠키 + 일반적 TLS/HTTP2 + JS 정상 + 낮은 요청량 + 정상 세션
  → 여러 신호가 서로 잘 맞음. 통과.
- **B 클라이언트**: 데이터센터 IP + Chrome UA + Python 계열 통신 지문 + 쿠키 없음 + 초당 여러 페이지
  → 여러 축에서 **동시에 모순**. 강하게 걸림.

Alibaba도 2025~ 신형 Bot Management를 **"multi-dimensional fingerprint detection"** 으로 설명하며
ClientID·JA3·JA4·HTTP/2 지문을 조합한다고 공개.

## 4. 정정·핵심 원칙 (오해 방지)

1. **실브라우저 강점의 이유 = "잘 위장"이 아니라 "아예 위장 안 함".**
   TLS/HTTP2/IP/쿠키/JS가 전부 **진짜로 일관**됨. 스크래퍼(curl-impersonate 등)가 죽는 지점이
   바로 이 다층 일관성 — UA는 Chrome인데 TLS 스택이 아니라서 축끼리 모순. 우리는 그 모순이 원천적으로 없음.

2. **유일한 크랙 포인트 = ③ JS층 자동화 노출.**
   실브라우저라도 `navigator.webdriver`·CDP 아티팩트·`--enable-automation`이 새면 JS 환경에서
   "자동화됨"으로 잡혀 다시 모순. 구분:
   - **Aside 제품 에이전트로 사용** = 자동화 노출 억제(그게 제품 핵심) → 안전 쪽.
   - **외부 CDP(포트 9333)에 직접 붙는 것**(테스트 방식) = 노출 가능 → **실사용은 반드시 Aside 에이전트 경로.**

3. **滑块 = 밴 아님.** "증명해라"로 재분류된 신호. 통과하면 신뢰 쿠키가 붙어 세션이 진정됨.
   → **사람이 풀고 세션은 계속.** 단 **자동 재시도·연타 금지**(그게 의심도를 올림).
   *(앞서 "风控 뜨면 무조건 정지"는 과했음 — 정정.)*

4. **"0.8~3초 랜덤" 같은 안전 수치는 없다.** Alibaba가 공개한 적 없고, 인간 행동 위장 알고리즘을
   넣는다고 정상 유저로 인정되지도 않음. **목표는 마법 숫자가 아니라 "자동화 발자국 최소화".**
   랜덤 딜레이는 밴 회피 주술이 아니라 **폭주를 안 하는 것의 부산물**일 뿐.

5. **WAF ≠ Taobao 운영값.** 위 인용은 Alibaba Cloud WAF Bot Management 공개 문서로 *"다차원 탐지가
   기술적으로 뭔가"* 를 보여줄 뿐, Taobao.com 실제 风控 모델의 **점수식·임계값은 비공개**.
   → "임계값을 맞춘다"는 접근은 성립 불가. **발자국 축소**만이 통제 가능한 변수.

## 5. 자동화 경계 (설계 결론)

| 적극 자동화 (안전) | 사람이 승인 (비가역·보안) |
|---|---|
| 중국어 번역 · 검색 보조 · 옵션 해석 · 상품 비교 · 장바구니 담기 | 로그인/보안 검증 · **滑块** · 배송지 중요 변경 · **주문 확정** · **결제** |

- 탐지 회피가 아니라 **정당한 개인 보조의 경계**.
- 덤: 오작동으로 엉뚱한 상품 20개를 주문하는 사고도 함께 차단.

## 6. 실무 수칙 (통제 가능한 변수만)

우선순위 순:

1. **볼륨(읽기 팬아웃) — 실질 리스크 1순위.** 상품 50개 병렬 열기 금지, **순차·소량**.
2. **환경 일관성.** 실프로필·실쿠키 유지, **GPU 실렌더**(소프트렌더 llvmpipe는 VM 냄새 → 켜둘 것),
   **고정 주거용 IP**(한국 집 IP면 OK), VPN/IDC IP 금지, **계정↔디바이스↔IP 1:1**.
3. **세션.** 장시간 연속 금지, 신규 계정은 워밍업(둘러보기·소액 먼저) 후 민감 동작.
4. **challenge.** 뜨면 사람이 풀기, **자동 재시도 금지**.
5. **비가역 동작.** 결제·주문·주소변경은 **Guard 승인**.
