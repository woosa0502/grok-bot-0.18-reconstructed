# PWA 일반 답변이 숨겨지는 문제 수정

## 문제와 변경

일반 사용자 메시지에 대한 모델 답변은 `reply_to`로 원문을 참조할 수 있다. 이 참조만으로 별도 스레드가 되는 것은 아니다. 실제 분기 대화에는 호스트가 `branched: true`를 기록한다.

PWA는 모든 부모 참조를 스레드로 접어, 정상적으로 저장된 답변 대신 `답글 1개`만 표시했다. 사용자가 제보한 두 답변도 서버에 존재했지만 메인 화면에서 숨겨져 있었다. 답변이 숨겨진 상태에서 활동 표시가 `응답 후 처리 중`으로 바뀌어 혼란을 더했다.

수정 후에는 다음과 같이 동작한다.

- 일반 부모 참조가 있는 답변·첨부·선택 카드·승인 카드를 메인 대화에 표시한다.
- 명시적으로 분기된 항목만 접고, 첫 번째 일반 메시지를 스레드의 시작점으로 삼는다.
- 부모 페이지가 아직 없거나 참조가 순환하면 내용을 숨기지 않는다.
- 메인 화면의 응답 후 활동 표시는 실제로 표시되는 항목만 근거로 삼는다.

저장된 대화나 모델 응답은 변경하지 않았다. 기존 답변은 PWA를 새로고침하면 표시된다. 앞서 관측한 답변 후 실행 시간 자체를 줄이는 변경은 아니다.

## 검증과 적용

- 원래 구현에서 일반 답변·중첩 스레드·부모가 없는 항목·카드 표시 회귀 4개가 모두 실패했다. 수정 후 해당 회귀와 분기 카드/승인 사례를 포함한 5개가 통과했다.
- Node 26.5.0에서 `npm run check`, `npm run frontend:build`, PWA 빌드가 통과했다. 기존 선택적 브라우저 검사 2개는 기본 전체 검사에서 생략된다.
- 운영 PWA의 실제 사용자 대화에서 수정 전에는 두 답변이 숨겨지고 잘못된 답글 버튼 2개가 표시됐다. 수정 후에는 두 답변 본문이 표시되고 잘못된 버튼이 사라졌다. 브라우저 예외는 관측되지 않았다.
- 별도 검증용 봇에 PWA UI로 새 메시지 1개를 전송했다. 실제 모델의 답변에는 해당 사용자 메시지에 대한 `replyToId`가 있고 `branched`는 없었다. 답변 본문이 메인 화면에 표시되고 실행 종료 후 중지 버튼이 사라졌다.
- 정적 파일 12개의 운영 HTTP 응답 해시가 빌드 결과와 일치했다. 기존 해시 이름의 자산을 보존하고 새 진입 문서를 교체했다. 호스트/PWA 서버 재시작과 사용자 작업 중단은 없었다.
- 별도 읽기 전용 검증자가 서버/데스크톱의 분기 계약, 원시 대화, 수정 전후 화면, 배포 자산을 대조했다.

검증 환경은 운영 Windows PWA 서버에 연결한 PC Chrome의 모바일 크기 화면이다. 새 폰 자동화 실행을 주장하지 않는다.

## 재현과 근거

```bash
PATH=/home/hoon/.local/share/mise/installs/node/26.5.0/bin:$PATH \
  node --test grok-mobile-belmont-pwa/tests/visible-replies.test.mjs
```

개인 대화·브라우저 프로필을 포함한 원시 자료는 Git에서 제외한다. 로컬 근거 디렉터리는 `data/artifacts/pwa-visible-reply-20260908/`이다.

- `raw-transcript-tail.json`: 원래 답변과 분기 메타데이터
- `regression-before.txt`, `regression-after.txt`: 실패 재현과 수정 결과
- `before.json`, `before.png`, `after.json`, `after.png`: 실제 사용자 화면 비교
- `probe-receipt.json`, `probe.json`, `probe.png`: 새 메시지의 실제 모델 응답과 표시
- `deployment.json`: 정적 파일별 빌드/배포 해시
- `check.txt`, `frontend-build.txt`, `mobile-build.txt`: 검사 및 빌드 기록

추가 모델 호출 없이 기존 답변이 표시되는지만 다시 확인하려면 로컬 `observe.mjs after`를 실행한다. `observe.mjs probe`는 검증용 봇에 새 요청을 보내므로 단순 조회용으로 사용하지 않는다.
