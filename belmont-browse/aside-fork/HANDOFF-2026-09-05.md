### A1. 광고 차단 엔진 문법 범위 — **[완료, §0-1]** (아래는 착수 전 기술)
- **차이**: 원본은 adblock-rust(brave). 포크는 Chromium `subresource_filter` 규칙 파서 + `url_pattern_index`.
  EasyList 3,172줄, EasyPrivacy 49줄이 파서 미지원으로 버려짐(`$redirect`·`$csp`·`$removeparam`·정규식 규칙·
  `:-abp-*`/`:style()` 등 절차형 선택자·`$rewrite`·`$important` 등).
- **근거**: `test/adblock/result-2026-09-05.json` `parseErrorCount`, 내부 페이지의 subscriptions invalidLines(200줄 상한).
- **다음 한 수**:
  1. 버려진 줄 전수 분류: `AsideAdBlockService` 상태의 invalidLines는 200줄 상한이므로, 임시로
     `kMaxInvalidLinesPerSource`를 크게 올려 덤프하거나 오프라인 도구(`components/subresource_filter/tools/`의
     rule parser를 쓰는 작은 실행파일)로 EasyList를 돌려 "옵션별 개수" 표를 만든다.
  2. 개수 큰 순서로 구현: (a) `$important`(우선순위) (b) `$redirect`/`$redirect-rule`(리소스 대체 — 빈 JS/1x1 gif
     내장 필요) (c) `$removeparam` (d) `$csp` (e) 정규식 규칙(`/…/`, `url_pattern_index`는 REGEXP 타입 지원, 파서만
     확장) (f) 절차형 선택자(렌더러 쪽 JS 필요 → A6과 묶기).
  3. 대안 검토: adblock-rust를 Rust FFI로 직접 넣기(Chromium 151은 Rust 툴체인 있음. `third_party/rust`에 crate
     vendoring 필요 — 의존 crate 수십 개라 비용 큼). 1~2단계 결과가 "차단 결과 차이 없음"이면 하지 않는다.

## 3. 함정 (이번 세션에서 실제로 밟은 것)

- **pkill/pgrep 자기매치**: 같은 bash 명령 안에 패턴 문자열이 다른 곳(예: 뒤의 ninja 실행줄)에 그대로 있으면 `pkill -f`가
  셸 자신을 죽인다(Exit 144, 이후 편집이 안 됨). 패턴은 `'[n]inja …'`처럼 쓰고, 죽이기와 실행을 한 명령에 섞지 않는다.
- 백그라운드 relink는 최상위에서 `setsid nohup … &`로. 괄호 서브셸 안에서는 로그 파일이 안 생기는 경우가 있었다.

  `BubbleDialogDelegateView` 생성자 비공개; `LabelButton::label()` protected; `base::JSONReader::Read`는 옵션 인자 필수;
  `SimpleURLLoader::DownloadToString` 콜백은 `std::optional<std::string>`.
- `network::ResourceRequest::is_outermost_main_frame`는 "주 프레임 문서가 **보낸** 요청"이라는 뜻(클라이언트 힌트용).
  탐색 여부 판단에 쓰면 주 프레임의 모든 하위 요청을 건너뛴다(이번 세션 버그).
- WebUI를 파일 디렉터리에서 서비스할 때 `$i18n{…}` 치환은 직접 해야 한다(`aside_adblock_internals_ui.cc` 참조).
- 내부 페이지 mojo: 원본 JS 바인딩을 쓰려면 메시지 ID를 맞춰야 한다(A2).

### 7-2. 환경 사고 — 이것 때문에 하루가 두 배로 걸렸다

### 7-5. 함정 — 오늘 실제로 밟은 것

§3의 옛 함정 목록에 더한다.

- **공유 헤더를 두 번에 나눠 편집하면 남이 깨진다.** G2가 `multi_contents_view.h`에 접근자만 먼저
  넣고 멤버를 나중에 넣는 사이(12:07~12:08) G1이 빌드를 돌려 세 타깃이 깨졌다.
  → **선언과 사용을 한 hunk에 같이 넣어, 저장하는 매 순간이 컴파일되는 상태로 둔다.**
  공유 파일(`chrome/browser/BUILD.gn`, `chrome/browser/ui/BUILD.gn`, `browser_prefs.cc`,
  `chrome_content_browser_client.cc`, `chrome_browser_main_extra_parts_profiles.cc`)은
  **편집 직전에 다시 읽고** 최소 hunk만.
- **`git add -N`을 빼먹으면 패치에 안 잡힌다.** 새 파일은 추적되지 않으면 `git diff`에 안 나온다.
  오늘 G1이 6개, G3이 6개, G4가 **24개**, G7이 4개를 뒤늦게 intent-to-add 했다.
  뒤늦게 하면 그 파일이 **통째로** 패치에 들어간다(그 그룹의 변경분만이 아니라 이전 세션 작업까지).
- **`pkill -f`가 자기 셸을 죽인다.** 또 밟았다. 패턴이 자기 명령줄과 겹치면 `[x]` 트릭도 소용없다.
  → `pgrep -f '^/home/hoon/chromium/src/out/aside/chrome --no-sandbox --user-data-dir=/tmp/aside-ui-G1'`
  처럼 **앞을 고정**할 것.
- **Aside 확장을 로드하면 라이브 데몬(21420)에 붙는다.** 그래서 확인용 크롬에는 확장을 한 번도
  올리지 않았고, 확장이 있어야만 보이는 것은 전부 "라이브 확인 필요"로 남겼다(L1~L10).
  대신 쓸 수 있는 우회 두 가지가 오늘 검증됐다:
  - **가짜 데몬**: `ASIDE_DAEMON_BASE_URL=http://127.0.0.1:<포트>`로 자기 응답기를 가리킨다
    (G1 §7, G5 §2). 세로탭 작업·채팅 행, 데몬 인증 악수, Omaha 응답까지 전부 이걸로 확인했다.
  - **가짜 홈**: `ASIDE_HOME=/tmp/...`로 `accounts.json`을 물린다. 진짜 `~/.aside`를 안 건드린다.
- **`--no-first-run`을 빼면 최초 실행 약관 창에서 시작이 멈춘다.** DevTools 서버가 열리기 전이라
  CDP가 빈다(HEAL §실행 확인).
- **이 트리의 함정 (§3 목록에 추가)**: `display::Screen::GetScreen()` 없음 → `Get()`.
  탭 관찰자 콜백은 `OnTabChangedAt(tabs::TabInterface*, int, TabChangeType)`.
  `GURL::host()`는 `std::string_view`를 돌려준다. `ui::base/models/simple_menu_model.h`는
  `ui/menus/simple_menu_model.h`로 옮겨졌다(타깃도 `//ui/menus`).
  `ui::kColorIconActive` 없음. 헤더에 raw pointer 멤버를 쓰면 `[chromium-rawptr]`로 막힌다.
- **`BubbleDialogDelegateView`의 그 생성자는 private다.** 쓰려면 그 헤더의 friend 목록에
  자기 클래스를 등록해야 한다(상위 버블 30여 개가 전부 그렇게 되어 있다).
- **탭이 아닌 WebContents에서도 탐색 스로틀이 불린다.** 옴니박스 팝업 미리 띄우기 등.
  `tabs::TabInterface::GetFromContents()` 대신 `MaybeGetFromContents()`를 쓸 것(HEAL §11의 SEGV).
- **`base::AppendToFile`은 파일이 없으면 실패한다.** 없으면 `base::WriteFile`로 만들고 그 뒤 append
  (G5 §1-다. 이것 때문에 컴포넌트 업데이트 로그가 **한 줄도** 안 쓰이고 있었다).
- **`views::View`의 `GetChildrenInZOrder()`를 재정의한 자식에 뷰를 붙이면 그려지지 않는다.**
  크로미움은 이 목록으로 그리기와 히트 테스트를 둘 다 한다. "배치에는 들어가 폭은 차지하는데
  그려지지도 잡히지도 않는다"가 이 증상이다(G7 §5).
- **FlexLayout에서 기본 크기 0인 자식은 주 배분 패스에서 빠진다**(`FilterZeroSizeChildreIfNeeded`).
  남는 높이를 먹일 빈 칸을 넣을 때는 1×1 DIP를 줄 것(G7 §4).
